Quick Tutorial

처음 설치하는 학생을 위한 전체 흐름

conda는 파이썬 실습 환경을 깔끔하게 분리해 주는 도구입니다. Windows에서는 설치 뒤에 Anaconda Prompt와 PowerShell 쪽 설정을 한 번만 정리해 두면 이후 실습이 훨씬 편해집니다.

  • Anaconda 설치 파일을 내려받아 설치합니다.
  • 설치가 끝나면 Anaconda Prompt에서 conda --version을 확인합니다.
  • conda init powershell로 PowerShell 초기화를 진행합니다.
  • 관리자 권한 PowerShell에서 Set-ExecutionPolicy -ExecutionPolicy RemoteSigned를 실행합니다.
  • 모든 터미널을 닫고 다시 PowerShell을 열어 conda activate base가 되는지 확인합니다.
Anaconda 다운로드
1. Anaconda 설치

아래 링크에서 Anaconda를 내려받아 설치하세요. 학생 안내에서는 혼동을 줄이기 위해 Anaconda 하나만 사용합니다.

다운로드 링크 https://www.anaconda.com/download/success?reg=skipped 권장 흐름 - 설치 파일 실행 - 기본 옵션으로 설치 - 설치 완료 후 Finish

설치가 끝나면 시작 메뉴에 Anaconda Prompt가 생기고, 이후 단계에서 conda 명령을 사용할 수 있습니다.

2. 설치 후 Windows에서 Anaconda Prompt 열기

시작 메뉴에서 Anaconda Prompt를 검색해 실행하세요. 설치가 잘 되었다면 conda 명령을 바로 사용할 수 있습니다.

(base) C:\Users\Student> conda --version conda 25.1.1

위와 비슷하게 버전이 보이면 정상입니다. 숫자는 설치 시점에 따라 다를 수 있습니다.

3. Anaconda Prompt에서 PowerShell 초기화

아래 명령을 실행해 PowerShell이 conda를 인식하도록 초기 설정을 추가합니다.

(base) C:\Users\Student> conda init powershell no change C:\Users\Student\anaconda3\Scripts\conda.exe no change C:\Users\Student\anaconda3\Scripts\conda-env.exe modified C:\Users\Student\Documents\WindowsPowerShell\profile.ps1 ==> For changes to take effect, close and re-open your current shell. <==

출력은 환경마다 조금 다르지만, 마지막에 현재 셸을 닫고 다시 열라는 안내가 나오면 정상적으로 적용된 것입니다.

4. 관리자 권한으로 Windows PowerShell 실행

시작 메뉴에서 Windows PowerShell을 검색한 뒤, 관리자 권한으로 실행을 선택하세요.

Windows PowerShell Copyright (C) Microsoft Corporation. All rights reserved. PS C:\Windows\system32>

프롬프트가 PS C:\Windows\system32>처럼 보이면 다음 단계로 진행하면 됩니다.

5. 실행 정책 설정

관리자 PowerShell에서 아래 명령을 실행해 로컬 PowerShell 프로필 스크립트가 실행될 수 있도록 설정합니다.

PS C:\Windows\system32> Set-ExecutionPolicy -ExecutionPolicy RemoteSigned Execution Policy Change The execution policy helps protect you from scripts that you do not trust. Do you want to change the execution policy? [Y] Yes [A] Yes to All [N] No [L] No to All [S] Suspend [?] Help (default is "N"): A

여기서는 A를 입력해 승인하면 됩니다. 다만 컴퓨터 상태에 따라 이 확인 질문이 아예 나오지 않을 수도 있는데, 그런 경우에는 따로 입력하지 않아도 괜찮습니다. 이미 설정이 적용되어 있거나 추가 확인이 필요 없는 상태일 수 있습니다.

6. 모든 창을 닫고 다시 PowerShell에서 최종 확인

설정이 끝났으면 열려 있던 Anaconda Prompt와 PowerShell을 모두 닫고, 일반 Windows PowerShell을 다시 열어 아래처럼 테스트합니다.

PS C:\Users\Student> conda activate base (base) PS C:\Users\Student> conda info --envs # conda environments: # base * C:\Users\Student\anaconda3

base 앞에 별표가 보이면 성공입니다. 만약 바로 되지 않으면 PowerShell을 한 번 더 완전히 껐다가 다시 열어 보세요.

API Recap

OpenAI API 빠른 복습 가이드

OpenAI Recap

처음에는 이것만 이해해도 충분합니다

OpenAI Python SDK에서는 보통 client.responses.create()를 사용합니다. 여기서 가장 중요한 생각은 아주 단순합니다. model은 어떤 AI를 쓸지, input은 이번에 AI에게 보여줄 대화 기록이라고 이해하면 됩니다.

  • model: 어떤 모델을 쓸지 고르는 값
  • input: 질문 하나 또는 대화 기록 전체
  • instructions: 답변 말투와 규칙
  • temperature: 답변이 얼마나 다양하게 나올지
  • max_output_tokens: 답변 최대 길이
  • tools: 모델이 쓸 수 있는 추가 능력
  • reasoning: 깊게 생각하게 하는 설정
Responses API에서는 예전의 messages를 떠올리면 이해가 쉽습니다. 다만 이름이 messages가 아니라 input이고, 그 안에 여러 개의 대화 항목을 넣는다고 생각하면 됩니다.
1. 준비

패키지 설치와 .env 파일

API 키는 코드에 직접 쓰지 말고 .env 파일에 넣어 두는 습관이 좋습니다. 이렇게 하면 키를 실수로 GitHub에 올릴 가능성이 줄어듭니다.

pip install openai python-dotenv
# .env OPENAI_API_KEY=sk-your-key-here OPENAI_BASE_URL=https://api.openai.com/v1

OPENAI_BASE_URL은 공식 OpenAI API를 쓸 때 보통 생략해도 됩니다. 여기서는 학생들이 “API 주소를 어디에 넣는지” 한눈에 보도록 예시로 함께 적었습니다.

2. client 만들기

키와 주소를 코드에서 읽어 오기

import os from dotenv import load_dotenv from openai import OpenAI load_dotenv() client = OpenAI( api_key=os.getenv("OPENAI_API_KEY"), base_url=os.getenv("OPENAI_BASE_URL", "https://api.openai.com/v1"), )

load_dotenv()는 .env 파일 내용을 읽어 메모리에 올립니다. 그다음 OpenAI()가 그 값을 사용해 API와 연결합니다.

3. 대화 기록 넣기

input을 messages처럼 생각하면 쉽습니다

아래 예시는 사용자가 어떤 말을 했고, 어시스턴트가 어떻게 답했는지를 리스트로 넣는 방식입니다. 여기에 instructions, temperature, max_output_tokens 같은 키를 함께 붙일 수 있습니다.

response = client.responses.create( model="gpt-4o-mini", instructions="학생에게 쉬운 한국어로 짧고 친절하게 설명해 줘.", input=[ {"role": "user", "content": "knock knock."}, {"role": "assistant", "content": "Who's there?"}, {"role": "user", "content": "Orange."}, ], temperature=0.7, max_output_tokens=120, text={"verbosity": "low"}, ) print(response.output_text)
예시 출력 Orange who?

temperature는 답변의 자유로움이고, max_output_tokens는 답변 최대 길이, text={"verbosity": "low"}는 말 수를 조금 줄여 달라는 느낌으로 이해하면 됩니다.

4. 이어서 묻기

대화 목록에 직접 이어 붙이면 더 자연스럽습니다

처음 배우는 단계에서는 messages 리스트를 직접 늘려 가는 방식이 더 눈에 잘 들어옵니다. 방금 한 대화가 그대로 쌓인다는 점이 분명하게 보이기 때문입니다.

messages = [ {"role": "user", "content": "파이썬이 왜 재미있는지 짧게 설명해 줘."}, ] response = client.responses.create( model="gpt-4o-mini", input=messages, ) assistant_text = response.output_text print(assistant_text) messages.append({"role": "assistant", "content": assistant_text}) messages.append({"role": "user", "content": "이번에는 한 문장 예시도 같이 보여 줘."}) next_response = client.responses.create( model="gpt-4o-mini", input=messages, ) print(next_response.output_text)

이 방식은 “대화 공책에 한 줄씩 계속 적어 가기”처럼 이해하면 쉽습니다. 사용자의 말과 어시스턴트의 답을 둘 다 리스트에 넣어 두었다가, 다음 요청 때 다시 함께 보내는 방식입니다.

5. 생각 더 하게 하기

reasoning으로 더 꼼꼼하게 답하게 만들기

reasoning을 지원하는 모델에서는 reasoning 옵션으로 생각의 깊이를 조절할 수 있습니다.

response = client.responses.create( model="gpt-5", input="두 가지 프로젝트 아이디어를 비교해서 장단점을 표처럼 정리해 줘.", reasoning={"effort": "medium"}, ) print(response.output_text)

effort는 생각의 힘입니다. low는 빠르게, medium은 균형 있게, high는 더 꼼꼼하게 답하려는 느낌입니다.

6. 도구 붙이기

tools를 쓰면 모델에 추가 능력을 붙일 수 있습니다

예를 들어 웹 검색 도구를 붙이면 모델이 답을 만들 때 최신 웹 정보를 참고할 수 있습니다.

response = client.responses.create( model="gpt-5", input="오늘의 AI 관련 소식을 하나 찾아 한국어로 짧게 요약해 줘.", tools=[{"type": "web_search"}], tool_choice="auto", ) print(response.output_text)

tools는 “모델이 사용할 수 있는 도구 목록”, tool_choice="auto"는 “필요하면 알아서 도구를 써도 좋아”라는 뜻입니다.

Key Guide

자주 쓰는 키를 쉬운 말로

model

어떤 AI 두뇌를 쓸지 정하는 값입니다. 속도, 가격, 성격이 모델마다 다릅니다.

input

이번 요청에서 모델에게 보여 줄 내용입니다. 짧은 문자열 하나일 수도 있고 대화 목록일 수도 있습니다.

role

누가 말했는지 표시합니다. 보통 user와 assistant를 자주 봅니다.

content

실제로 말한 내용입니다. 질문 문장이나 이전 답변 문장이 여기에 들어갑니다.

instructions

전체 답변 스타일과 규칙입니다. “한국어로 쉽게 설명해 줘” 같은 방향을 잡아 줍니다.

temperature

답변의 다양성을 조절합니다. 낮으면 차분하고 일정하고, 높으면 더 자유롭게 나옵니다.

max_output_tokens

답변이 너무 길어지지 않도록 대략적인 최대 길이를 잡아 주는 값입니다.

text.verbosity

말 수를 얼마나 줄이거나 늘릴지에 가까운 느낌입니다. low면 짧게, 높을수록 더 자세하게 답하려 합니다.

messages.append(...)

대화를 이어 갈 때 자주 쓰는 기본 패턴입니다. 새 사용자 말과 이전 답변을 리스트에 차곡차곡 추가합니다.

tools

모델이 사용할 수 있는 바깥 능력 목록입니다. 검색, 파일 탐색, 함수 호출 같은 기능을 붙일 수 있습니다.

tool_choice

도구를 꼭 쓰게 할지, 필요할 때만 쓰게 할지 정합니다. auto는 자동 판단입니다.

reasoning.effort

생각의 깊이를 조절하는 값입니다. reasoning 지원 모델에서만 사용하며, 높을수록 더 꼼꼼해집니다.

모든 키를 한 번에 다 외울 필요는 없습니다. 처음에는 model, input, instructions, temperature, max_output_tokens 정도만 익혀도 충분히 많은 실습을 할 수 있습니다. 그다음 필요할 때 대화 리스트 누적 방식, tools, reasoning을 하나씩 붙이면 됩니다.
